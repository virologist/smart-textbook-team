# multi-agent-patterns — 多代理协作与循环模式库

> 第一原则：**任何循环都必须有显式收敛判据与迭代上限**。无上限的循环等于停摆风险——这不是保守，是 3 轮不收敛就烧掉整个预算的现实。

## 何时使用

- 设计任何涉及 ≥2 个代理的协作流程
- 某个流程反复不收敛、或不知道该不该继续循环
- 需要判断「这个任务该并行还是串行」

---

## 模式一：Generator-Critic（生成—批评）

**结构**：Generator 产出 → Critic 独立评判 → 不合格则带证据返修 → 循环

**适用**：内容生产 + 质量控制（本团队：writer ↔ examiner）

**收敛判据**：`verdict = pass`，即无 P0/P1 blocking 项

**上限**：3 轮。第 3 轮仍失败 → 停止，通知用户并附完整 3 轮证据链
（触限停机契约见「人在回路」小节）

**关键约束**
- Generator 与 Critic **必须是不同代理**——自判等于没判
- Critic 输出必须是**结构化裁决**（verdict/blocking/advisory/evidence），不是「感觉还行」
- 返修指令必须**具体到行号与期望**，不是复述 Critic 原话
- Critic 只标三类阻断（正确性缺陷 / 需求未满足 / 数据完整性破坏）；风格偏好一律 advisory

**反模式**：Critic 顺手把内容改了（越界）；返修指令模糊导致同一问题反复出现（应在第 2 次即切换策略）

---

## 模式二：Plan-Execute-Reflect（计划—执行—回看）

**结构**：Planner 出规格 → Executor 按规格实现 → 回看覆盖度

**适用**：需求模糊、需要结构化拆解的场景（本团队：architect → writer → examiner 覆盖度回看）

**收敛判据**：设计规格中全部要素被覆盖且达标（本团队：design §B 知识块全覆盖 + Bloom 层级达成）

**上限**：2 轮。第 2 轮回看后规格要素仍未全覆盖 → 停机，附两轮覆盖度对照表
（触限停机契约见「人在回路」小节）

**关键约束**：Planner 不产出执行细节数据，只产出规格与验收标准；回看只看「契约内是否达成」，不追加契约外要求

---

## 模式三：Evidence Spiral（证据螺旋，H15）

**结构**：执行中发现证据缺口 → 标 `[待核实]` → 专职 Retriever 补检索 → 回填复核

**适用**：任何需要外部事实支撑的生产（本团队：教材数据与引用）

**收敛判据**：`[待核实]` 清零，或用户明确接受遗留清单

**上限**：2 轮。第 2 轮回填后 `[待核实]` 未清零且用户未明确接受遗留清单 → 停机，附遗留清单
（触限停机契约见「人在回路」小节）

**关键约束**：**缺口必须标注而非编造**——这是防幻觉的最后防线。回填后必须复核（不是填完就算过）

---

## 模式四：Retry-with-Strategy-Switch（重试—换策略）

**结构**：失败 → 同方式重试 → 仍失败 → **换策略** → 再失败 → 升级用户

**适用**：任务级失败处理

**收敛判据**：任务闭合（成功或明确放弃）

**上限**：同方式 2 次 + 换策略 1 次 = 3 次。第 3 次仍失败 → 升级用户，附三次尝试记录
（触限停机契约见「人在回路」小节）

**策略切换映射（根因 → 动作）**

| 根因 | 判据 | 换什么策略 |
|------|------|-----------|
| A 证据缺失 | 需要的数据检索库里没有 | 转 Retriever 补检索，不逼 Generator 硬编 |
| B 理解偏差 | 指令歧义导致跑偏 | 编排者重写指令 + 给具体改法示例 |
| C 能力边界 | 任务超出角色定义 | 拆解为更小子步骤，或给参考片段（仍由该成员整合） |
| D 不可抗力 | 工具全挂 / 红线内容 | 直接停止，通知用户 |

**反模式**：同一句话重复发 3 次期待不同结果（这不是重试，是噪音）

---

## 模式五：Fan-out / Fan-in（扇出—聚合）

**结构**：一个任务拆成 N 个无依赖子任务并行 → 各自产出到不同路径 → 编排者聚合

**适用**：多知识点检索、多图并行设计、R3 分批核验

**收敛判据**：全部分支返回，或有分支明确失败

**上限**：分支数 ≤ 5（超出后聚合成本高于并行收益）

**关键约束**
1. 分支间**无数据依赖**方可扇出
2. 每个分支写**独立路径**，禁止同文件并发写
3. 用 `correlation_id` 聚合，**不做交叉合并**（分支产出保持原样，合并决策权在编排者）
4. 部分分支失败时：其余分支结果保留，只重跑失败分支

---

## 模式选型速查

| 场景 | 用哪个 |
|------|--------|
| 内容需要质量把关 | Generator-Critic |
| 需求模糊需拆解 | Plan-Execute-Reflect |
| 需要外部事实支撑 | Evidence Spiral |
| 任务失败要重试 | Retry-with-Strategy-Switch |
| 多个独立子任务 | Fan-out / Fan-in |

---

## 并行 vs 串行判据（决策树）

```
下游是否需要上游的输出？
├─ 是 → 串行
└─ 否 → 是否写同一文件？
         ├─ 是 → 串行（或重定向路径后并行）
         └─ 否 → 并行（分支数 ≤5，用 correlation_id 聚合）
```

## 人在回路（到上限/触限时的停机契约）

> 第一原则的补全：**「有上限」不等于「停下来之后有交代」**。本节把 5 个模式各自的
> 上限值，统一绑定到四个要素——**停机动作 / 交付物 / 交回谁 / 用户可做的决定**。
> 读完这一节，任何人拿到「已触限」的信号，都不需要再猜下一步该做什么。

**适用范围**：本节只管**协作循环的停机契约**（触限后怎么办）。裁决放行的车道口径
（绿/黄/红道定义与放行方式）不在此复述——口径 SSOT = `references/decision-lanes.md`，
本节只引用不重述。**红道动作永远人工**，不存在「模型置信度够高就自动放行」。

**四要素定义**（5 个模式共用，措辞一致）：
- **停机动作**：停止什么、不许做什么（可执行动作，非态度声明）
- **交付物**：随停机信号一起交出的证据（缺失证据的停机视为未停机）
- **交回谁**：本包层级的接收方（管家节点 / 编排者 / 用户）
- **用户可做的决定**：用户收到停机信号后**能直接回话执行的** 2–3 个选项

### 5 个模式的停机契约

| 模式 | 触发条件（上限值） | 停机动作 | 交付物（必须附） | 交回谁 | 用户可做的决定 |
|------|------|---------|------|--------|--------|
| 模式一 Generator-Critic | 第 3 轮仍 `verdict ≠ pass` | 停止返修循环；**不再派第 4 轮 Generator**；Critic 停止出裁决 | 完整 3 轮证据链：每轮 Generator 产出 + Critic 结构化裁决（verdict/blocking/advisory/evidence）+ 逐轮 blocking 项对照 | 编排者 → 用户（编排者先核证据链完整性，再通知用户） | ① 放宽上限并指定新的收敛判据（写明放宽到几轮、以什么判据收口）② 换策略重跑（换 Generator 或换 Critic 分工）③ 终止，按当前产出交付并声明遗留阻断项 |
| 模式二 Plan-Execute-Reflect | 第 2 轮回看后规格要素仍未全覆盖 | 停止回看循环；**不追加第 3 轮规格**；Planner 停止出规格 | 两轮覆盖度对照表：design §B 知识块逐项 × 两轮达成状态 + 未覆盖项清单与根因归类 | 编排者（规格归编排者所有，合并决策权在编排者）；编排者判定后转用户 | ① 放宽上限并指定新的收敛判据（写明放宽到几轮、以什么判据收口）② 缩小任务范围（砍掉未覆盖项后重跑）③ 终止，按当前产出交付并声明未覆盖项 |
| 模式三 Evidence Spiral | 第 2 轮回填后 `[待核实]` 未清零，且用户未明确接受遗留清单 | 停止检索回填；**禁止编造补齐**（缺口必须继续标注）；Retriever 停止补检索 | 遗留清单：每条 `[待核实]` 的位置 + 缺什么 + 已检索过的来源 + 仍未检索到的原因 | 编排者 → 用户（遗留清单是用户「明确接受遗留」这一决策的必要输入） | ① 接受遗留清单并按现状继续（写明接受哪些条目）② 指定新检索源/新检索式后重跑第 2 轮 ③ 终止，按当前产出交付并逐条声明未核实项 |
| 模式四 Retry-with-Strategy-Switch | 同方式 2 次 + 换策略 1 次 = 3 次仍失败 | 停止重试；**禁止第 4 次尝试**（原样重发 = 噪音，见模式四反模式）；根因若为 D 不可抗力 → 直接停止 | 三次尝试记录：每次的动作 + 依据的根因分类（A/B/C/D）+ 失败证据；根因为 D 时附完整工具错误输出 | 编排者 → 用户（根因为 D 时直接通知用户，不经中间层） | ① 指定新的根因判定与换策略动作后重跑（写明新根因与对应策略）② 放宽上限并指定新的收敛判据（写明放宽到几次、以什么判据收口）③ 终止，按当前产出交付并声明失败项 |
| 模式五 Fan-out / Fan-in | 分支数超出 5（协议硬上限：分支数 ≤ 5） | 停止新开分支；**已开分支不取消**（其余分支结果保留，见本模式关键约束④）；编排者停止发起扇出 | 分支清单：已开分支的 `correlation_id` + 各自路径 + 各自状态（成功/失败）+ 未开分支的待办项 | 编排者（聚合决策权在编排者，不做交叉合并） | ① 授权扩到第 6 个及以后分支（写明授权几支、分支怎么拆）② 改为串行分批跑已授权的分支 ③ 终止，按已完成分支交付并声明未跑分支 |

### 停机信号的共同要求

1. **停机 = 停止 + 交代**，不是「不吭声地停下」。四项要素缺任一项 → 视为未停机，
   循环不得重启。
2. **证据先于结论**：交付物必须附在本包既有的产物形态里（证据链 / 对照表 / 清单 /
   分支状态），不得用「已尽力」「问题复杂」等描述性语句替代。
3. **交回谁 = 责任明确**：编排者是本包默认的聚合与仲裁方；管家节点只在**跨任务、
   跨批次**的裁决场景接手（口径见 `references/decision-lanes.md`）；需要用户决策时
   一律**由编排者转交用户**，成员不得越过编排者直接向用户提问。
4. **用户的三个选项是穷举的**：用户回话只能从「放宽上限 / 换策略重跑 / 终止并按当前
   产出交付并声明遗留」三类中选（或明确指定等价动作）。**不接受「先放着」**——
   未闭环的停机必须有一个显式终态。
5. **红道动作永远人工**：无论用户选哪个选项，若下一步动作落在红道（触及交付边界 /
   影响权威源 / 难逆转），仍须人工确认——**选项的存在不等于自动放行**。

## 通用反模式清单

- 循环无上限或无收敛判据
- 触限后只停机不交代（缺交付物 / 缺交回对象 / 缺用户可选动作）
- 把「用户没回话」当成「用户同意继续」——静默续跑
- Critic 与 Generator 同一代理
- 上下文整段复制传递（应给路径）
- 并行分支写同一文件
- 失败后原样重发（不换策略、不给新证据）
- 部分分支失败就丢弃全部结果
