## 3. 缺陷清单

### BUG-1 — `progress.py block` / `resolve` 在 progress.md 缺失时抛未捕获 Traceback

| 项 | 内容 |
|---|---|
| **严重度** | **缺陷（BUG）** |
| **位置** | `scripts/progress.py:566-568`（`_mutate_blocking`） |
| **触发条件** | `--work-root` 可写但未 `init`（无 `运行态/progress.md`） |

**最小复现**

```bash
mkdir -p /tmp/wrA
python3 scripts/progress.py --work-root /tmp/wrA block --item i --source s
```

**实际输出**（RC=1）

```
Traceback (most recent call last):
  File ".../scripts/progress.py", line 736, in main
    add_blocking(wr, args.item, args.source)
  File ".../scripts/progress.py", line 568, in _mutate_blocking
    text = p.read_text(encoding='utf-8')
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/wrA/运行态/progress.md'
```

`resolve` 同症状（`scripts/progress.py:563` → `_mutate_blocking` 同一行）。

**期望输出**：与同文件 `update_phase`（`progress.py:458-459`）、`show`（`progress.py:651-653`）口径一致——
```
ERROR  progress.md 不存在: /tmp/wrA/运行态/progress.md; 请先 init
```
退出码 2。

**根因**：`_mutate_blocking` 第 568 行直接 `p.read_text()`，**缺少 `if not p.exists()` 前置检查**。同文件的 `update_phase` 与 `show` 都做了该检查 ⇒ 三兄弟行为不一致。

**影响面**：编排者误操作（对未 init 的工作区调用 block/resolve）时得到 Python 栈回溯而非可读错误；违反「错误路径须友好、不得裸 Traceback」的 CLI 契约。`update` 已正确处理 ⇒ 说明是遗漏而非设计。

### BUG-3 — `progress.py book init --word-budget` 接受负数，导致整章从 `check_book` 解析中消失

| 项 | 内容 |
|---|---|
| **严重度** | **缺陷（BUG）** |
| **位置** | `scripts/progress.py:700`（参数定义）/ `:278`（`init_book` 落盘）；消费侧 `scripts/check_cross_chapter.py:186`、`scripts/check_book.py:58` |

**最小复现**

```bash
mkdir -p /tmp/wrF
python3 scripts/progress.py --work-root /tmp/wrF book init \
  --textbook T --chapters ch01 --audience "职业本科" --word-budget -200
# 实际：OK  book initialized   RC=0
# 产物 book-spec.md：
#   total_word_budget: -200
#     - id: ch01
#       word_budget: -200
```

**实际输出**（`check_book.py --json`）

```
[FAIL] 5.1 章清单 / book-spec: book-spec.md 无章清单（chapters 为空）
```

**期望输出**：`--word-budget` 为负应被参数校验拒绝（exit 2），如 `--audience` 非法值那样（`progress.py:709-712` 已有该模式）。

**根因（双重）**
1. `progress.py book init` 对 `--word-budget` **无下界校验**（`--audience` 有，`--chapters` 空值有，唯独 budget 没有）。
2. 下游解析用 `\d+` 匹配（**只匹配非负整数**）：
   - `check_cross_chapter.py:186` `word_budget: (\d+)` ⇒ `-200` 不匹配 ⇒ **该章整条从 spec 中消失**；
   - `check_book.py:58` `total_word_budget:\s*(\d+)` ⇒ `-200` 不匹配 ⇒ `total_budget=0` ⇒ **5.1「全书字数偏差 ≤5%」判据整条静默跳过**。

**影响面**：静默降级 —— 负预算不但不被拒绝，还导致 **5.1 字数校验与 5.3 单章门禁双双失效**，且报错信息误导为「无章清单」。这是本轮最值得修的一处。

### BUG-4 — `check_book.py` 5.3 判据的 detail 只取子进程输出最后一行，真实失败原因丢失

| 项 | 内容 |
|---|---|
| **严重度** | **缺陷（BUG）** |
| **位置** | `scripts/check_book.py:182-187` |

**最小复现**

```bash
python3 scripts/check_manuscript.py --work-root "$WR" --chapter ch01 --strict
```


```bash
$ python3 scripts/watchdog.py --work-root "$W" --task-id t-zero --channel heartbeat
VERDICT=ALIVE          # 心跳 age=24.4s，阈值 0 却判 ALIVE
  channel=heartbeat age=24.4s alive=True
```

`--timeout-s -5` 则判 DEAD（`alive = age <= -5` 恒假）。**两个反直觉结果并存**：0 → 永远 ALIVE（阈值失效），负数 → 永远 DEAD（误杀）。建议对 `timeout_s < 1` 拒绝或归一到默认值（当前默认 60）。
